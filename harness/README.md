# 工程自检

`harness/` 保存开发和验收辅助脚本，不存放 Agent 运行时业务代码。

## 运行方式

在项目根目录完成 Git 初始化和依赖同步后运行：

```powershell
uv run --locked python harness/check_project.py
```

脚本使用 Python 标准库并调用只读 Git 命令，不写文件、不访问网络、不调用模型，也不读取本地 `.env`。命令中的 uv 仍可能按锁文件同步虚拟环境；脚本自身只读。退出码 0 表示列出的工程检查通过，退出码 1 表示存在问题。

## 检查范围

- Phase 0 原有文档及 Phase 1 源码、测试、CURRENT_STATE、验收和构建记录等必需文件是否存在。
- 当前 Python 与 `.python-version` 一致；运行时、开发依赖、uv_build 应用包和 Ruff / pytest 配置符合已确认的 Phase 1 决策；原 pytest/Ruff 锁定版本未被无关升级。
- `uv.lock` 可以解析并包含项目和工具；完整锁文件新鲜度另用 `uv lock --check` 验证。
- 环境示例格式正确、无重复变量，敏感字段留空，默认只监听本机。
- 通过 `git check-ignore --no-index -z --stdin` 验证敏感路径被忽略、示例与工程文件不被忽略，并识别已经跟踪的应忽略文件；NUL 分隔避免 Windows 换行转换影响路径。
- 对 Git 已跟踪及未忽略的新文件中，扩展名为 `.py`、`.md`、`.toml`、`.lock` 或属于必需文件白名单的文本，检查 UTF-8 无 BOM、LF、末尾换行和行尾空格；这覆盖 `git diff --check` 未覆盖的未跟踪新文件。
- Markdown 本地文件链接存在且在项目内；不校验外部网址、文档标题锚点或复杂 Markdown 语法。
- 对上述范围的文本检查少量常见密钥模式，发现时只报告文件名，不输出密钥。

本脚本随阶段演进。Phase 1 将原先“无运行时依赖、仅两项开发工具、non-package”的限制替换为已确认的基础设施契约，保留安全和文本检查。后续改变 Python、依赖或文件清单时，应先说明理由并同步调整检查，不能为了绕过失败随意关闭规则。

## 限制

启发式密钥检查不保证发现任意格式凭据，也不扫描被忽略的用户数据、二进制文件或 Git 历史。提交前必须人工审查差异。真实泄密应撤销并轮换凭据，单纯增加忽略规则不能消除泄露。

工程自检不等于应用测试。Phase 0 只有工具验证；Phase 1 必须另行运行真实 pytest 后端基础测试，不能用“0 个测试”表示验收通过。要求见 [质量规范](../docs/quality.md)，实际结果见 [阶段验收](../docs/ACCEPTANCE.md)。
