# Nova 分阶段路线图

## 执行方式

每次只实施一个经用户明确发起的阶段。阶段开工前说明范围、依赖和技术变化；交付时记录实际验收结果与遗留问题。阶段验收后停止，不因路线图存在就自动继续。

以下是方向性规划，没有承诺日期。后续阶段可以在开工前进一步拆分或缩小范围；变更需要同步更新目标、计划及决策记录。Phase 0 已完成；当前获准实施的是 Phase 1 后端基础架构，尚未授权进入 Phase 2。

## Phase 0：项目基础设施与工程规范

- **交付物：** 独立项目目录；协作规则与项目文档；Python/uv/pytest/Ruff 配置；依赖锁文件；安全配置示例；Windows 指南；工程自检脚本；本地 Git 初始化与执行记录。
- **验收条件：** 原有用户文件保持原样；文档链接和配置有效；锁文件一致；格式、静态检查、自检及忽略规则检查通过；实际工具版本和命令结果已记录。
- **退出标准：** [Phase 0 质量清单](quality.md) 的必需项全部满足；未实现业务功能；明确报告尚无业务测试；剩余问题不阻塞本阶段；交付后立即停止。

## Phase 1：后端基础架构

- **交付物：** FastAPI 工厂、lifespan、集中路由和 `/health`；类型化环境与 `.env` 配置；安全统一日志与错误响应；sqlite3 连接、事务、关闭和非破坏性初始化；离线 pytest；Windows 启动和验收记录。
- **范围：** 用户新指令替代 Phase 0 的原“最小对话闭环”安排；不接入 DeepSeek、不实现聊天、前端、长期记忆或业务表。
- **验收条件：** 生命周期、健康、配置、错误、日志和数据库的关键正常及失败测试通过；真实本地服务健康检查和数据库初始化完成；静态、格式、锁文件与工程自检通过；实际命令、数量、差异和风险均记录。
- **退出标准：** [阶段验收](ACCEPTANCE.md) 全部关键项通过，CURRENT_STATE、build-log 和进度已更新，已知问题不阻塞本阶段；立即停止，不自动执行 Phase 2。

原 Phase 1 中的 Provider 和 Web 对话闭环保留为后续候选需求，需用户重新确定切片与顺序，不能据旧路线图自动实现。

## Phase 2：稳定人格与 SQLite 会话

本节保留 Phase 0 的方向性规划。开工前需结合尚未实施的最小对话闭环重新拆分和确认，不表示当前已授权这些功能。

- **交付物：** 版本化人格配置；SQLite 会话及消息持久化；存储层；初始化与非破坏性升级说明；会话恢复接口和对应 Web 操作。
- **验收条件：** 重启后能恢复会话；不同会话互不串用；人格配置可追踪版本；上下文超长有明确策略；事务失败不会生成部分写入；数据库路径与文件不进入 Git。
- **退出标准：** 已验证存储、恢复与人格加载的正常和失败路径；数据结构、保留策略及备份操作有文档；破坏性迁移不作为隐含步骤执行。

## Phase 3：用户可控的长期记忆

- **交付物：** 记忆提议与写入规则；记忆来源与更新时间；查看、修改、删除、关闭记忆能力；检索及注入上下文的最小实现；行为验收样例。
- **验收条件：** 不把模型推测直接当作用户事实；用户可查看保存了什么及来源；关闭后不继续写入；修改与冲突有确定规则；删除覆盖原记录和派生摘要/索引，备份中的保留边界明确；删除后的记忆不会从旧摘要重新注入。
- **退出标准：** 用户控制闭环和隔离规则通过测试；误记、过期与敏感信息处理规则公开；先评估 SQLite 可满足的方案，再根据实际需求决定是否增加检索依赖。

## Phase 4：受权限约束的工具执行

- **交付物：** 最小工具注册与执行接口；参数校验；权限及确认策略；超时、输出大小和执行范围限制；必要审计记录；少量有明确用途的工具。
- **验收条件：** 默认能力最小；未授权调用、越界路径、不合法参数和超时会被拒绝或安全终止；外部写入、执行命令等动作按策略获得授权；提示注入与模型输出不能扩大权限；日志不泄露密钥或完整用户内容。
- **退出标准：** 已验证授权、拒绝、取消与失败路径；已公开工具能力和风险边界；没有默认启用的任意命令执行器；所有真实外部写入的验收遵守用户授权。

## Phase 5：VPS 部署与运维

- **交付物：** 适合单用户的部署说明和必要配置；访问控制与 TLS；进程管理；密钥注入；备份、恢复、升级和回滚流程；日志保留及资源限制。
- **验收条件：** 未授权访问被拒绝；密钥不写入镜像或仓库；SQLite 位于持久存储；备份恢复实际演练；升级失败可回滚；运行与错误可观察且日志脱敏。
- **退出标准：** 经用户明确授权后才执行真实部署；实际部署验证和恢复记录完整；未开放未经审查的调试接口；成本与维护责任明确。若部署未执行，只能交付准备工作，不能声称已上线。

## Phase 6：Flutter 客户端（按需）

- **交付物：** 基于稳定后端接口的 Flutter 最小客户端；平台构建与运行说明；本地凭据处理及会话交互。
- **验收条件：** 复用现有 API；不在客户端嵌入 Provider Key；网络失败、取消与会话恢复行为明确；目标平台上完成实际构建与基本交互验证。
- **退出标准：** 用户选定的平台完成验收；发布应用商店或分发安装包另行授权；不因移动端需要而复制后端业务逻辑。

## 跨阶段关注点

- 依赖、模型名称、API 能力和费用在使用时重新核实，不在 Phase 0 写死尚未验证的外部能力。
- 不根据路线图预先安装业务依赖；新增依赖说明用途、影响和验证方式。
- 自动化测试默认离线；涉及费用、个人数据、数据库破坏或外部写入的验证单独说明并遵守授权。
- 性能、成本、记忆质量和人格一致性先建立可重复的样例和测量方法，再设置合理阈值。
