# Nova V3.0 分阶段路线图

## 执行原则与当前状态

每次只实施用户明确发起的阶段，先核实实际代码与 GitHub 状态，再确定最小范围、接口、依赖和验收。路线图描述方向，不授权自动开发、调用付费 API、发布或合并 main。

当前为 **V3.0 Phase 2 候选实现与验收**，由用户本轮明确授权。在既有FastAPI、SQLite聊天历史、Ollama、Web和GPU Manager上增加三层人格只读基线、纯上下文编排及评估工具，不代表完整成长系统或Phase 2人工验收已完成。Phase 1真实游戏进程切换由用户选择暂不执行，27B真实推理因安全资源门槛不足待验；这些独立遗留项不改写为通过，本轮也不运行27B。实际结果见 [阶段验收](ACCEPTANCE.md)、[Phase 2审计](PHASE2_AUDIT.md) 和 [当前计划](../PLANS.md)。

旧“Phase 0 工程初始化 / Phase 1 后端基础架构”与此前 V2 的执行记录属于历史，证据保留在 [开发记录](progress.md)、[阶段验收](ACCEPTANCE.md) 和 GitHub；以下统一使用 V3.0 阶段编号。

## 跨阶段接口约束

- Persona、记忆和成长状态独立于底层模型；业务核心不依赖 HTTP 请求、具体 Provider SDK 或数据库连接。
- Phase 2仅有`PersonaManager.snapshot()/reload()`、会话临时状态和内部提案验证；无运行时审批/应用、完整成长持久化或人格数据库。Canon/Persona更新与回退须经源控审核和部署，详见 [D020](decisions.md)。
- 下一阶段记忆只能向纯编排器提供带来源的低信任候选，必须先解决可信用户身份、隔离、纠错/删除和授权；不能把当前单机thread隔离直接当作多用户隐私边界。未来检索扩展应保留当前消息与核心身份预算，不绕过资源门禁。
- Model Router 解析模型与策略；所有生产本地加载仍由同一个 GPU Manager 准入和回收，AUTO 恢复不预加载。
- 用户事实、虚构设定、外部知识和模型推断保留来源；外部数据不能授予工具权限或覆盖系统规则。
- 默认离线测试使用合成内容和临时资源；真实 GPU、游戏、云端、浏览器和手机验证分别记录，不能互相替代。
- VPS、Flutter、向量检索和其他推理后端按实际需求单独规划，不提前引入分布式组件或多 Agent 运行框架。新增依赖或架构调整记录 [技术决策](decisions.md)。

每阶段适用检查参见 [质量规范](quality.md)。必需项失败或未执行时保留相应未验收状态；Phase 2交付后停止，由负责人确认验收并由用户明确决定后续阶段。正式远端合并仍需用户批准。
