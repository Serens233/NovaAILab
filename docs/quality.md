# Nova 质量与阶段验收规范

## 基本要求

质量检查应与当前阶段的风险匹配。Phase 0 的工程基础验收历史保留；Phase 1 新增后端基础设施测试和真实本地运行检查，不以测试数量替代行为验收。

每次交付记录：检查对象、实际命令、退出码、结果摘要、未执行项及原因。检查失败先修复再复查；只报告实际执行的结果。记录入口为 [开发记录](progress.md)。

## 通用检查命令

在项目根目录的 PowerShell 中逐条执行；前一条失败时先处理，不将最后一条的成功当作整组通过。

```powershell
uv lock --check
uv sync --locked
uv run --locked pytest -ra
uv run --locked ruff format --check .
uv run --locked ruff check .
uv run --locked python harness/check_project.py
git diff --check
git status --short --branch
```

| 检查 | 通过条件 |
| --- | --- |
| 原有内容保护 | 不删除用户数据或无关文件；工程文件只按确认范围定向更新；原日期目录保留，变更与 Phase 0 快照可比较 |
| 解释器与依赖 | 实际运行 CPython 3.14.10；`uv.lock` 由 uv 生成且匹配配置；锁定同步成功；Phase 0 的 pytest/Ruff 未无关升级 |
| 格式与静态检查 | Ruff 格式检查和静态检查退出码均为 0 |
| 工程自检 | 必需文件齐全；TOML 可解析；本地文档链接有效；编码、空白和配置契约符合 `harness/README.md` 的检查范围；退出码为 0 |
| 忽略规则 | 使用 Git 规则检查代表性密钥、虚拟环境、缓存、数据库及日志路径被忽略；`.env.example`、工程配置、文档和锁文件可以跟踪 |
| 密钥与数据 | `.env.example` 的密钥为空；拟交付文件中不含真实凭据和用户数据；本地 `.env`、运行数据库和测试产物不纳入 Git，不删除已有数据 |
| 文档一致性 | 模块职责、版本基线、目录规划和命令一致；未来功能明确标为未实现 |
| 阶段边界 | 当前只实现后端基础架构；不接入 DeepSeek、聊天、前端或长期记忆，不建业务表；验收后停止 |

`git diff --check` 不检查首次初始化时尚未跟踪的文件，因此不能单独证明新文件没有空白问题；由工程自检补查其声明范围内的文件，并人工审阅交付清单。

工程自检中的密钥及忽略规则检查是防误配置措施，不能证明任意文本都不含秘密，也不能代替提交前审查。新增文件与实际差异仍需检查。

## pytest 的使用边界

Phase 0 只安装并配置 pytest，版本命令仅证明工具可运行；该阶段未用空测试集制造通过记录：

```powershell
uv run --locked pytest --version
```

版本命令成功只表示工具可用。pytest 退出码 5 表示没有收集到测试，不能作为成功。Phase 1 必须运行实际后端基础测试，不能继续用版本检查代替。

从 Phase 1 起，在 `tests/` 随功能增加测试：

```powershell
uv run --locked pytest
```

新增功能至少覆盖核心成功行为与有实际风险的失败路径。只为文档、注释或易撤销配置调整增加镜像式断言没有价值。

## 后续功能验证原则

| 范围 | 应验证的重点 |
| --- | --- |
| API | 合法输入、边界输入、校验错误、稳定错误响应、取消及超时 |
| Provider | 可替换性；鉴权失败、限流、超时、上游错误及流中断；重试边界 |
| 人格与上下文 | 配置加载与版本、上下文隔离、长度限制、用户控制 |
| SQLite | 临时数据库测试、事务原子性、恢复、升级与失败回滚 |
| 长期记忆 | 来源、授权写入、冲突、关闭、删除及派生数据清理 |
| 工具 | 权限拒绝、参数校验、路径边界、超时、输出限制和外部写入授权 |
| 前端 | 关键输入、等待、失败、重试、取消与恢复体验 |

默认测试使用假的 Provider 和临时资源，不需要 API Key，不调用真实模型，不产生费用，也不修改个人数据库。真实 API、部署和外部工具冒烟测试另行记录环境、授权、成本边界及结果，不放入默认测试路径。

目前不设置缺少基线依据的覆盖率、性能或“智能程度”硬门槛。需要时先定义用户场景和可重复测量方法，再在阶段开工前确定阈值。

## 依赖与架构变更

新增或升级依赖前说明用途、许可证或维护方面的明显限制、引入范围和验证方法；更新 `pyproject.toml` 与 `uv.lock`，运行相关检查。Phase 0 的直接开发依赖为 pytest 和 Ruff；Phase 1 为 TestClient 新增 HTTPX2，其余直接依赖见决策和项目声明。

架构变化应在 [决策记录](decisions.md) 说明理由、替代方案和重新评估条件。数据库破坏性操作需说明数据影响、备份和恢复方式，并获得明确授权。

## 退出与报告

只有当前阶段的必需检查通过、交付物齐全且不存在阻塞问题时，才能标记完成。网络受限、工具缺失或检查未执行需要保留为未完成项，不能改写为通过。

报告应包含完成范围、实际检查结果、已知限制、未完成事项及下一阶段建议。阶段完成后停止；路线图和建议均不授权自动继续。

## Phase 1 必需行为验收

| 范围 | 必需验证 |
| --- | --- |
| 生命周期 | 启动初始化、退出清理、启动失败不就绪、多个应用实例状态隔离 |
| 健康 | 实际请求 `/health` 正常 200；数据库不可用或未就绪时安全 503，不泄露配置和路径 |
| 配置 | 默认值、UTF-8 `.env`、环境覆盖、类型/范围校验、可选空密钥、错误提示不回显敏感值 |
| 错误 | 已知应用错误、404、405、422、意外 500 结构一致，不向客户端返回堆栈或原始校验输入 |
| 日志 | 等级、JSON 格式、请求标识；合成敏感值在客户端、应用日志及服务器日志中不泄漏 |
| SQLite | 连接释放、提交、回滚、提交失败、关闭后拒绝、幂等初始化、未知/损坏数据库拒绝、已有数据不受破坏 |
| 本地运行 | 按 README 锁定同步后启动；配置 HOST/PORT 生效；健康和独立初始化可运行；实际停止进程 |

自动化默认离线，使用临时数据库和独立配置，不读取开发者真实 `.env`、不依赖真实 DeepSeek。Windows 管理员环境下不依赖 chmod 构造权限失败，使用可重复的非法路径或受控失败。

正式初始化只产生 Nova 元数据，不得包含聊天或记忆业务表。测试可在临时库创建合成事务表，用于验证提交和回滚；这些临时表不属于正式 schema。

交付时报告 pytest 实际通过、失败、跳过数量及退出码；运行记录集中在 [阶段验收](ACCEPTANCE.md)。由于当前 Git 无提交且文件未跟踪，`git diff --stat` 可能为空，必须另提供与 Phase 0 文件快照的真实差异摘要，不能伪称它覆盖全部改动。
