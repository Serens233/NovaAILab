# Nova UI-01 部署交接

## 本地部署

`scripts/run_local.py` 启动现有 FastAPI 与生产网关 `scripts/serve-local.mjs`。后者提供构建后的 SPA 和同源 API，深链接刷新也由 SPA 接管。Vite 开发服务器用于界面调试。真实模式通过生产网关访问后端。

启动器以专用数据目录保存 SQLite、GPU 状态和日志。测试目录和日常目录独立。只监听 127.0.0.1。管理令牌由启动器随机生成，仅在子进程环境传递。固定转发表与来源检查限制浏览器可发出的请求，前端只接本机 Nova。

这是单人本机部署：回环监听和浏览器来源检查不能认证本机其他程序，也不提供多用户隔离。不要将网关或后端暴露到公网；远程访问、渠道接入和多用户使用前必须另行设计认证及用户隔离。

删除对话只从当前数据库删除；之前人工创建或自动保存的数据库备份可能仍含该对话。备份需要用户自行识别和处理，程序不会擅自删除备份。

2026-11-04 审查修复：切换会话时会请求后端取消原生成；无法确认取消会提示用户。网络异常重试使用同一请求标识，避免重复提交。会话沿用其指定的 9B/4B 模型，并显示实际回复模型；其他模型不会静默替换。浏览器被关闭或崩溃时无法保证取消消息送达；回退原因仅在当前页面展示。测试：80 项单元测试通过，typecheck、lint、build 通过；网关 7 项通过。上述均未访问真实模型或私人聊天。

默认沿用 GPU Manager 的自动游戏检测、显存保护和空闲卸载。云端与实验模型在本地启动器中关闭。

升级到 2026-11-04 的 GPU 实例锁时，必须先正常停止所有旧版 Nova GPU Manager，等待其推理及卸载工作实际结束，然后再启动新版。旧版 TEMP 文件锁与新版 Windows 命名对象不能互相识别，禁止新旧版本混跑；Ollama 服务无需因此关闭。Linux 实例锁按用户目录隔离，不能当作跨用户互斥；Windows 与 WSL/Linux 的锁互不共享，不得同时运行两个 GPU Manager 控制同一个 Ollama。

## 回退

停止 UI-01 后可按原仓库说明运行 Next.js 前端。两个界面沿用同一后端代码，启动器默认指向各自的数据目录。保留数据目录即可保留历史。避免同时启动两套共享同一 Ollama 的 Nova GPU 管理器。
